# Flashing the WiiRemoteX ESP32 bridge

Use an original ESP32 with Bluetooth Classic support, such as ESP32-WROOM-32 / ESP32 DevKitC. ESP32-S3, C3 and C6 cannot replace it for the Wii-side Bluetooth Classic HID transport.

## Recommended method: ESP-IDF

Install ESP-IDF / `esptool.py`, connect the ESP32 by USB and identify its serial port.

If you built the firmware from source:

```bash
cd firmware/esp32
idf.py set-target esp32
idf.py build
idf.py -p <PORT> flash monitor
```

Examples:

```bash
idf.py -p COM5 flash monitor
idf.py -p /dev/ttyUSB0 flash monitor
```

## Flashing a GitHub Release package

The release ZIP contains the binaries plus `flash_args` and `flasher_args.json` generated by ESP-IDF. Those files are authoritative for offsets for that exact firmware build.

Extract the `esp32/` directory and run `esptool.py` from that directory using the offsets in `flasher_args.json`.

A typical ESP32 layout uses entries similar to:

```text
0x1000   bootloader.bin
0x8000   partition-table.bin
0x10000  wiiremotex_esp32_bridge.bin
```

Do **not** blindly reuse those example offsets if the packaged `flasher_args.json` says otherwise.

Example manual command after checking the metadata:

```bash
esptool.py --chip esp32 --port <PORT> --baud 460800 write_flash \
  0x1000 bootloader.bin \
  0x8000 partition-table.bin \
  0x10000 wiiremotex_esp32_bridge.bin
```

## After flashing

1. Reset the ESP32.
2. Open WiiRemoteX on Android or iPhone.
3. Select the **ESP32 Bridge** transport.
4. Connect to the bridge and wait for `BRIDGE_READY`.
5. Confirm the displayed firmware/protocol versions.
6. Start Wii pairing.
7. Press the Wii red SYNC button.
8. Record the result in `docs/hardware/COMPATIBILITY_MATRIX.md`.

For repeatable local bridge testing, use:

```bash
pip install -r tools/hil/requirements.txt
python tools/hil/bridge_smoke.py probe
python tools/hil/bridge_smoke.py pair
```

## Recovery

If the board becomes unresponsive:

- disconnect/reconnect USB power
- hold BOOT while initiating the flash if automatic bootloader entry fails
- erase flash only as a last resort because it also removes persisted bond information

```bash
esptool.py --chip esp32 --port <PORT> erase_flash
```

Then flash the complete release set again.
